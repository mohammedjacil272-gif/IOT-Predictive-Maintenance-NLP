## 1. Executive Summary

The Misata dataset is a synthetic industrial sensor dataset containing hourly readings for six assets over one year.

The structural, temporal, label, missingness, and window-boundary audits provide a basis for designing a leakage-aware predictive-maintenance experiment.

Important limitations:

- The dataset is synthetic, not real industrial telemetry.
- The work orders contain structured information, not technician free-text narratives.
- Sensor-text fusion has not been validated.
- No real-world industrial deployment performance can be claimed.
- At the time of this dataset audit, model training had not yet been performed. Subsequent sensor-only LSTM training and test evaluation are documented in MISATA_LSTM_TRAINING_REPORT.md.

## 3. Data Integrity and Structure

The original dataset integrity audit reported 10/10 structural checks passed.

No duplicate (asset_id, recorded_at) readings were identified.

The dataset is generated by Misata Studio and must be described as synthetic.

The six assets include:
- Screw compressors
- Conveyor drive
- Centrifugal pumps
- Induction motor

Different equipment types may have different operating characteristics. Avoid assuming one universal physical threshold applies to every asset.

These missing periods occur outside failure windows as well. Missingness is a dataset-wide property and is not established as a reliable early-warning signal.

## 5. Operating Modes and Sensor Anomalies

Operating modes include high, idle, normal, and stopped.

Stopped readings commonly contain zero vibration, motor current, discharge pressure, and rotor speed. These are systematic stopped-state values and should not automatically be treated as missing data.

Anomaly candidates include:
- Three negative bearing-temperature readings.
- Seven running readings with zero discharge pressure.
- Six running readings with zero motor current.
- One running reading with zero rotor speed.

No authoritative physical range metadata was available to prove these values invalid.

Recommendation: preserve the original readings. If necessary, introduce anomaly flags or conduct a sensitivity analysis rather than silently replacing values.

Operating-mode transitions were not established as an early-warning signal.

## 6. Target Label Audit

Existing target distribution:

- Positive: 897
- Negative: 51,663
- Positive rate: approximately 1.7066%

A reconstructed future-failure target using:

0 < hours_to_failure <= 24

produced 936 positives.

The two target definitions matched on 52,521 readings, with 39 mismatches.

The mismatches correspond to the final stopped reading at each failure event. These readings have false target labels and missing RUL.

This appears consistent with the dataset's label-generation convention. The original labels must not be silently overwritten.

Recommended prediction endpoints: running readings only.

Stopped readings may remain in historical input windows where appropriate.

## 8. Sliding Window Audit

Window length: 30 consecutive hourly readings.

All audited windows contain exactly 30 consecutive hourly timestamps.

| Split | Eligible windows | Windows containing stopped history | Windows with missing sensors |
|---|---:|---:|---:|
| Train | 25,410 | 897 | 6,291 |
| Validation | 12,957 | 443 | 2,643 |
| Test | 12,979 | 435 | 3,108 |

Historical windows can cross chronological split boundaries. Prediction labels remain protected by the purge policy.

Fit imputers and scalers using training data only.

## 9. Leakage Prevention

Do not use the following as model inputs:

- degradation_stage
- rul_hours
- next_failure_mode
- failure_next_24h
- Future failure-event information
- Post-failure corrective work-order information

The target must not leak into the input features.

Do not use information that would only become available after the prediction timestamp.

Potential categorical feature: operating_mode, provided it is available at inference time and encoded correctly.

Missingness indicators and operating mode should be evaluated through ablation rather than assumed predictive.

## 10. Sensor and Text Fusion Readiness

The dataset provides sensor time-series and structured work-order records.

It does not provide genuine paired sensor observations and technician free-text narratives suitable for validating a BERT-based text-fusion model.

Therefore:

**Sensor-text fusion status: NOT_VALIDATED**

Do not claim that a multimodal model has been trained or validated using this dataset.

A genuine paired, time-aligned sensor and technician-text dataset is required for fusion training and evaluation.

## 11. Recommended Experimental Protocol

1. Preserve the original dataset.
2. Use the chronological train/validation/test split.
3. Purge 24 prediction endpoints per asset at each split end.
4. Restrict prediction endpoints to running readings.
5. Build 30-hour historical windows.
6. Fit imputation and scaling transformations on training data only.
7. Exclude target, RUL, degradation stage, and future-event fields from input features.
8. Evaluate class imbalance explicitly.
9. Report precision, recall, F1, PR-AUC, and confusion matrices, alongside the chosen operating threshold.
10. Compare optional operating-mode and missingness-indicator features using ablation.
11. Keep synthetic-data results separate from real-world deployment claims.

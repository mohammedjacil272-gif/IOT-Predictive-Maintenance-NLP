# NLP Output Schema

**Status:** Version 1.0 — implementation-aligned draft  
**Owner:** Rafaz  
**Data status:** Current pipeline validated with synthetic fixture only

## 1. Purpose

This document describes the fields currently accepted and generated by the technician-log NLP pipeline. It distinguishes implemented fields from fields required for future genuine-data integration.

## 2. Input CSV contract

The current builder requires:

| Field | Status | Description |
|---|---|---|
| log_id | REQUIRED | Stable, non-empty log identifier. Duplicate IDs are rejected. |
| text | REQUIRED | Original technician-log text. |

The current synthetic fixture also contains:

| Field | Status | Description |
|---|---|---|
| unit_id | OPTIONAL in current code | Fixture equipment/unit identifier; genuine mapping is not verified. |
| cycle | OPTIONAL in current code | Fixture cycle value; genuine cycle semantics are not verified. |
| event_type | OPTIONAL | Source-provided event category. |
| component | OPTIONAL | Source-provided component value. |
| severity | OPTIONAL | Source-provided severity value. Not used as ground truth by the heuristic scorer. |
| generation_rule_id | OPTIONAL | Synthetic fixture generation rule identifier. |
| template_id | OPTIONAL | Synthetic fixture template identifier. |
| source_split | OPTIONAL | Source split label; fixture currently uses `fixture`. |

Additional columns are preserved by preprocessing when present.

## 3. Processed log output

Output: `artifacts/data/fd001_nlp_fixture/processed_logs.csv`

| Field | Status | Description |
|---|---|---|
| Original input fields | IMPLEMENTED | Input values are copied into the processed record. |
| original_text | IMPLEMENTED | Original text preserved for traceability and NER offsets. |
| normalized_text | IMPLEMENTED | NFKC normalization, whitespace collapse, trim and lowercase. |
| text_status | IMPLEMENTED | `ok`, `empty_text` or `invalid_text`. |
| severity_score | IMPLEMENTED | Heuristic score from 0 to 4. |
| severity_label | IMPLEMENTED | `unknown`, `low`, `medium`, `high` or `critical`. |
| severity_matched_terms | IMPLEMENTED | JSON-serialized matched severity evidence. |
| severity_explanation | IMPLEMENTED | Explanation of the heuristic result. |

The builder requires `log_id` and `text`. It does not currently require genuine equipment mapping or timestamp fields.

## 4. Entity output

Output: `artifacts/data/fd001_nlp_fixture/entities.jsonl`

Each entity record contains:

| Field | Status | Description |
|---|---|---|
| log_id | IMPLEMENTED | Source log identifier. |
| entity_text | IMPLEMENTED | Exact text slice from original input. |
| label | IMPLEMENTED | Entity category. |
| start | IMPLEMENTED | Inclusive Python string offset. |
| end | IMPLEMENTED | Exclusive Python string offset. |
| rule_source_id | IMPLEMENTED | Rule identifier used for extraction. |

Supported labels:

- COMPONENT
- FAULT
- SYMPTOM
- ACTION
- SEVERITY_TERM
- MEASUREMENT

NER is rule-based. No labeled real-world NER dataset or learned NER accuracy is established.

## 5. Severity output

Output: `artifacts/data/fd001_nlp_fixture/severity.csv`

Fields:

- log_id
- unit_id
- cycle
- source_split
- severity_score
- severity_label
- matched_terms
- explanation

Scores:

| Score | Label |
|---:|---|
| 0 | unknown |
| 1 | low |
| 2 | medium |
| 3 | high |
| 4 | critical |

The highest unnegated matching severity term wins. Negation handling uses a preceding text context window. This is a heuristic, not validated real-world ground truth.

## 6. Embedding output

Files:

- `artifacts/embeddings/fd001_nlp_fixture/embeddings.pt`
- `artifacts/embeddings/fd001_nlp_fixture/embedding_metadata.csv`

Embedding configuration:

| Property | Current implementation |
|---|---|
| Model | distilbert-base-uncased |
| Tokenizer | AutoTokenizer for the same model name |
| Maximum token length | 128 |
| Pooling | Attention-mask mean pooling |
| Dimension | 768 |
| Model parameters | Frozen; evaluation mode |
| Embedding input | normalized_text |

Embedding metadata fields:

- row_index
- log_id
- unit_id
- cycle
- source_split
- model_name
- max_length
- pooling
- embedding_dim

The current builder writes metadata in the same iteration order as the embedding tensor. A separate comprehensive alignment verification is still required before genuine-data integration.

## 8. Dataset classification

The current fixture is synthetic.

Its records must remain labelled as synthetic fixtures. They must not be presented as genuine technician logs or used to claim predictive improvement.

## 9. Current limitations

- No genuine paired sensor-technician dataset has been established.
- Equipment and cycle mappings have not been independently verified.
- Point-in-time availability timestamps have not been established.
- NER has not been evaluated against labeled real-world logs.
- Severity scores are heuristic.
- Exact model and tokenizer revisions are not currently recorded.
- Comprehensive embedding-to-metadata alignment validation remains outstanding.

## 10. Baseline protection

The frozen sensor-only FD001 baseline, its preprocessing, split, scaler, checkpoints and metrics must remain unchanged. No official test evaluation is authorized by this NLP schema.
